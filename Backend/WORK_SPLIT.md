# Разделение backend-работ: Golang и C# (MVP хакатона)

Основано на «Решение.pdf» и «таски.pdf» (КосмоХакатон 2026, ForestProof).
Оставлено только то, что требуется для сдачи MVP. Остальное — в конце.

## Принцип разделения

- **Golang** — всё, кроме вычислений: внешний источник, кэш, публичный API, запуск расчёта, отдача слоёв для карты.
- **C#** — вычисления (матан), растры, геометрия, отчёт, provenance.
- **Граница:** Go отдаёт C# «AOI → файлы растров + метаданные сцен»; C# возвращает Go «run → summary / changes / report».

## Golang

### 1. Внешний источник и кэш
- STAC Earth Search, коллекция `sentinel-2-l2a`: поиск, скачивание, локальный кэш.
- Fallback: при недоступности — воспроизводимый локальный кэш, статус `partial` (не удалять слой молча).
- Локальные файлы набора данных (CCI, CCI Change, GFC, MODIS) — найти и отдать как есть.

### 2. Каталог источников и SHA-256
- Проверка SHA-256 исходных файлов, журнал происхождения (`sources.csv`, `file_catalog.csv`, `scenes.csv`).
- Секреты и ключи не попадают в репозиторий (задача 44).

### 3. Публичный API `/api/v1`
- `POST /analyses` — принять GeoJSON или `aoi_id`, годы, профиль метода.
- `GET /analyses/{id}/status` — фаза, прогресс, предупреждения.
- `GET /analyses/{id}/summary` — площадь, `C_t`, `Eproj`, `L/U`, coverage, baseline, `R`, `Q`, статус доступности единиц.
- `GET /analyses/{id}/changes` — GeoJSON зон с evidence и вкладом.
- `GET /analyses/{id}/layers/{layer}` — ссылка на слой/тайл с легендой.
- `POST /analyses/{id}/reports` — запустить формирование отчёта.
- `GET /sources` — каталог источников, версий и хэшей.
- Валидация формы запроса, лимиты, коды ошибок.

### 4. Запуск расчёта и статусы
- Простая фоновая задача (без Redis), прогресс и таймаут.
- Статусы: `validating`, `running`, `complete`, `partial`, `units_unavailable`, `failed`.
- Идемпотентность: тот же `input_hash + method_version` → тот же результат.

### 5. Отдача слоёв для карты
- Отдавать слои AOI, AGB начало/конец, разность, GFC, MODIS, Sentinel-2 как файлы/тайлы для фронта.

## C#

### 1. Raster service
- Чтение `CCI_Biomass_{year}.tif` через `MaxRev.Gdal.Core`: канал 1 — AGB, канал 2 — AGB_SD.
- NoData/NaN — пропуск; ноль AGB — валидное значение.
- Проверка CRS, размеров, числа каналов, конечных значений.
- Валидная маска и доля валидного покрытия.

### 2. Геометрия
- Проверка Polygon/MultiPolygon, WGS 84, самопересечения (исправление с предупреждением).
- Репроекция в равновеликую метрическую CRS `EPSG:6933`.
- Площадь пересечения каждого пикселя `aᵢ`, сумма `A = Σaᵢ` (не по bounding box).
- Валидация допустимости: площадь ≤ 20 км², годы 2019–2024, `start < end`.

### 3. Вычисления
- Запас: `cᵢ,t = bᵢ,t × CF`, `Cₜ = Σ(cᵢ,t × aᵢ)`, `c̄ₜ = Cₜ / A`.
- Изменение: `Δt`, `ΔC`, `Eproj = −ΔC × 44/12`, `e = Eproj / (A × Δt)`.
- Неопределённость: `L`, `U`, `H = max(Eproj − L, U − Eproj)`, `coverage_t0/t1`.
- Годовая динамика `Cₜ` и `c̄ₜ` за 2019–2024.
- Baseline: `g`, `cbase,y`, `Ebase`; baseline родительского AOI для дочернего, суммирование по нескольким AOI.
- Единицы: `R = Ebase − Eproj − LK`, `UNC = min(1, max(0, H/R − 0.10))`, `Radj`, `B = Radj × 0.15`, `Q = floor(Radj × 0.85)`; разделение `Q = 0` и `Q` недоступен.
- Сценарная стоимость `V = Q × p` для 500 / 1500 / 4000 руб.
- Спектральные индексы `NDVI`, `NDWI`, `NBR`, `dNBR` на валидных пикселях Sentinel-2, SCL-маска 4–5 (строгая) и 4–7 (расширенная).
- Зоны изменений: порог, связные компоненты, площадь, вклад в `ΔC`, evidence из GFC/Sentinel-2/MODIS, статус причины «подтверждено / вероятно / не установлено»; защита от повторного учёта пожара.

### 4. Оркестратор расчёта
- Единый `AnalysisResult` с `method_version`, `data_version`, `run_id`, `created_at`.
- Все промежуточные значения для аудита, округление только итогового `Q`.
- Эксперимент: изменившийся AOI (`RU_VOLOGDA_02`) и контрольный (`RU_TVER_01`), SCL 4–5 vs 4–7, `k=1` vs `k=2`; сравнение `Eproj`, `H`, coverage, зон и `Q`.

### 5. Отчёт и provenance
- HTML/PDF/JSON: территория, период, итоговая таблица, динамика, карта, зоны, источники, метод, baseline, неопределённость, ограничения, параметры, хэши, `run_id` и дата.
- JSON-манифест, ссылки на источники и SHA-256.
- Пометка «потенциальные, не сертифицированные единицы».

### 6. Внутренний расчётный API
- Контракт, по которому Go-шлюз запускает расчёт и забирает `summary` / `changes` / `report`.
- Офлайн-режим: расчёт из локального кэша без внешних источников.

### 7. Тесты
- Формулы: ручной пример из ТЗ → `Q=395`, коэффициенты `0.47` и `44/12`, знаки `Eproj`/`Ebase`/`R`.
- Геометрия: полный/половинный/микропиксель, запрет bounding box.
- Baseline, единицы, неполное покрытие, округление вниз.

## Не входит в MVP хакатона

- Аутентификация и RBAC (в ТЗ 8.2 упомянуты, но `User/Organization` помечен «только при необходимости»; демо без персональных данных).
- PostGIS/БД и объектное хранилище S3 — для 4 AOI достаточно файлов набора данных.
- Redis/очередь, Docker, мониторинг/метрики, админка, антивирус, изоляция организаций.
- ML-модули (классификация причин, регрессия AGB, сегментация).
- Финансовые `NPV`/`IRR`, реестр транзакций и торговля.
- Блоки S и G ESG — только контекст, спутникового расчёта нет.

## Порядок работ

1. **C#**: Raster service (AGB/SD + маска).
2. **Go**: STAC + кэш + API-шлюз.
3. **C#**: coverage + годовая динамика + оркестратор.
4. **C#**: зоны изменений + индексы.
5. **C#**: отчёт; **Go**: отдача слоёв и статусов.
6. **Оба**: offline-режим, эксперимент, демо.
